Device (LiteRT) vs Host (cluster GGUF) fidelity — v0.2 open-ended

MAM-AI v0.2 · is the host proxy a good stand-in for the deployed device? · gpt-oss-120b judge both sides · 2026-06-11

The host proxy is validated. Phase B was generated on a host proxy (cluster llama.cpp + Q4_0 GGUF); the deployed app runs LiteRT-LM on-device. Re-running the same questions on the real device and scoring with the same judge:

  • Device tracks host closely on both tracks (SAQ + Healthbench) and both arms.
  • No-RAG (the clean, identical-input comparison): device is consistently slightly better — so the host numbers are a mildly pessimistic lower bound, not an overstatement.
  • +RAG: device ≈ host (device slightly higher recall; these arms also exercise device-side retrieval, so differences mix retrieval + generation).
  • Every Phase B conclusion holds on-device — low recall / weighted_met, safe-but-unhelpful, zero-dangerous floor.
  • Leaked chain-of-thought is host-only — 0 across all 669 device generations → confirmed a host-eval artifact, not device behavior.

Method

Same questions, two stacks, one judge. Host = the committed Phase B results (cluster, llama.cpp, gemma-4-E4B-it-Q4_0.gguf). Device = Gemma 4 E4B on the deployed LiteRT-LM stack, run via run_eval_device.py (adb push/trigger/pull) in fresh-process batches of 8 — a workaround for aggressive on-device process killing of long runs (root-caused as not screen-related). Both arms rescored by the pinned gpt-oss-120b @ medium judge. SAQ run in full (369/arm); Healthbench sampled (50/subset = 150/arm) as the full 2,339/arm is ~12 h/arm on-device.

Bottom line

Across both tracks and both arms, the LiteRT device tracks the host GGUF proxy closely. On the clean no-RAG comparison the device is consistently a hair better, so the host numbers are a mildly pessimistic lower bound — likely because Q4_0 GGUF is a touch lossier than the LiteRT bundle. The deployed model's quality and safety are therefore at least as good as the Phase B headline numbers, and every Phase B conclusion (low recall, safe-but-unhelpful, zero-dangerous) holds on-device. The leaked chain-of-thought seen on the rubric track is a host-eval artifact (manual GGUF template), absent on all 669 device generations.

Caveats. Same gpt-oss-120b judge both sides (its bias cancels in the device-vs-host Δ). No bootstrap CIs, and small per-subset n (esp. the HB 50/subset sample and whb n=20) — read single-subset deltas as indicative, not precise. One judge job (SAQ +RAG) failed once on a transient pypi timeout and was resubmitted. Device runs used fresh-process batches of 8 to survive on-device process killing.
